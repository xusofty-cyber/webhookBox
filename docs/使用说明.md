# HookBox 使用说明

> 版本 0.2.0 ｜ 更新日期 2026-10-21

---

## 一、快速开始

三步，十分钟。

### 第 1 步：装 App

把 `app-debug.apk` 传到手机安装。首次打开会请求通知权限，**必须允许**，否则收不到提醒。

### 第 2 步：填中转地址

点右上角齿轮进「设置」页，填两个值：

| 字段 | 值 |
|---|---|
| Worker 地址 | `https://your-domain.com/hookbox` |
| RELAY_TOKEN | 见服务器 `~/projects/hookbox/.env` |

保存后自动开始连接，顶部状态变成**已连接**就成功了。

> 地址不要带结尾的 `/`，也不要带 `/ws`。程序会自己拼 `/ws?token=...`。

### 第 3 步：在平台上填回调地址

以 GitHub 为例：

```
https://your-domain.com/hookbox/hook/github?token=<RELAY_TOKEN>
```

发一条测试，手机应该立刻弹通知。

## 二、App 使用说明

### 2.1 界面

```
┌────────────────────────────────────┐
│ HookBox ●已连接            🔍  ⚙  │  ← 顶栏：状态点 / 搜索 / 设置
├────────────────────────────────────┤
│ [全部级别][信息][警告][错误][来源▾] │  ← 筛选
├────────────────────────────────────┤
│ 今天                                │
│ ┌──────────────────────────────┐   │
│ │ [信息] github        16:04:12 │   │
│ │ GitHub · acme/api             │   │
│ │ build completed / failure     │   │
│ │ 点开查看完整内容 ›            │   │
│ └──────────────────────────────┘   │
└────────────────────────────────────┘
点任意一条 → 详情页：标题/正文全量 + 完整原始 payload
```

### 2.2 状态灯含义

| 显示 | 含义 | 要做什么 |
|---|---|---|
| 未连接 | 服务没启动，或刚停止 | 进「设置」打开接收开关 |
| 连接中… | 正在握手 | 等 1~2 秒 |
| 已连接 | 长连接正常，能实时收 | 无需操作 |
| Ns 后重连 | 断线了，正在退避等待 | 一般不用管，会自动恢复 |

重连是指数退避 + 随机抖动，最长 60 秒一次。网络恢复后会自动连上。

### 2.3 消息列表与详情

- 列表按日期分组（今天 / 昨天 / 具体日期），顶部可按级别（信息 / 警告 / 错误）和来源筛选，右上角放大镜可搜索标题、正文、来源和原始内容
- 每条消息有级别徽标：绿色 `info`、橙色 `warn`、红色 `error`；左侧色条同色
- 列表里只显示预览（标题 2 行、正文 3 行），**点任意一条进详情页看完整内容**：标题、正文不限行数全量展示，下方有原始 payload（JSON 自动美化缩进、等宽字体、可切换长行横滑），支持长按选择、复制正文 / 复制原始内容、系统分享
- 左滑某条可删除本地记录；详情页右上角也可删除
- 最多显示最近 500 条，本地 SQLite 存储；在「设置 → 本地消息」可一键清空
- 新消息到达时也会弹系统通知，点通知直达该条消息的详情页
- 每次（重）连成功后自动补拉最近 200 条历史，按 id 去重，补拉的消息不弹通知

### 2.4 保活设置（重要）

Android 会主动杀后台进程，国内 ROM 更激进。**不做这一步，锁屏一段时间后就收不到了。**

点「去设置」会跳到系统的电池优化页面，把 HookBox 设为「不受限制」。除此之外还要按厂商补：

| 厂商 | 路径 |
|---|---|
| 小米 / Redmi | 设置 → 应用设置 → 应用管理 → HookBox → 省电策略「无限制」+ 自启动打开 |
| 华为 / 荣耀 | 设置 → 应用 → 应用启动管理 → HookBox 改为「手动管理」，三个开关全开 |
| OPPO / 一加 | 设置 → 电池 → 应用耗电管理 → HookBox → 允许后台运行 + 允许自启动 |
| vivo | 设置 → 电池 → 后台高耗电 → 允许 HookBox |
| 三星 | 设置 → 电池 → 后台使用限制 → 从「休眠应用」里移除 |

通用补充：

- 在多任务界面把 HookBox **下拉加锁**，防止「一键清理」带走
- 不要用「绿色守护」「黑阈」这类工具清理它
- 通知栏里 HookBox 的常驻通知**不要划掉**（划掉等于停服务）

即使全做了也可能偶尔被杀。这是系统机制，不是程序缺陷。真正要求「一条都不能丢」的场景，需要走厂商推送通道（华为 Push / 小米 Push 等）。

## 三、平台接入

### 3.1 URL 规则

```
https://<你的域名>/hookbox/hook/<source>?token=<RELAY_TOKEN>
                                  └──┬──┘
                                  自定义标签
```

`<source>` 随便起，只影响 App 里显示的来源标签。建议用平台名或项目名：`github`、`gitlab`、`stripe`、`uptime`、`blog-cms`。

三种鉴权方式，按平台能力选：

| 方式 | 适用 | 安全性 |
|---|---|---|
| URL 带 `?token=` | 所有平台 | 中（token 会出现在平台后台和日志里） |
| `X-HookBox-Signature` HMAC | 支持自定义 header 的平台 | 高 |
| 平台原生签名（GitHub / GitLab） | 对应平台 | 最高 |

### 3.2 GitHub

**仓库 → Settings → Webhooks → Add webhook**

| 字段 | 值 |
|---|---|
| Payload URL | `https://your-domain.com/hookbox/hook/github` |
| Content type | `application/json` |
| Secret | 与服务器 `GITHUB_SECRET` 一致（没配就留空） |
| SSL verification | Enable |
| Which events | 按需勾选，或 Send me everything |

配了 Secret 之后，URL 上**不需要**再带 `?token=`，签名就是鉴权。

**支持的事件与显示效果：**

| 事件 | App 标题 | App 正文 | 级别 |
|---|---|---|---|
| push | `GitHub · owner/repo` | 最新 commit message，没有则 `N commits` | info |
| pull_request | 同上 | `opened: 标题` | info |
| issues | 同上 | `opened: 标题` | info |
| workflow_run | 同上 | `build completed / failure` | 失败时 **error** |
| release | 同上 | `published: v1.2.0` | info |
| 其他 | `GitHub · 事件名` | `action` 字段 | info |

**去重**：用 `X-GitHub-Delivery` 头，同一投递重复到达只入库一次。

**验证**：加完 webhook，GitHub 会立刻发一个 `ping` 事件，手机上应该收到一条。之后在 webhook 详情页的 **Recent Deliveries** 里能看到每次投递的响应码。

### 3.3 GitLab

**项目 → Settings → Webhooks**

| 字段 | 值 |
|---|---|
| URL | `https://your-domain.com/hookbox/hook/gitlab` |
| Secret token | 与服务器 `GENERIC_SECRET` 一致 |
| Trigger | 按需勾选 |

GitLab 用 `X-Gitlab-Token` 明文比对，不走 HMAC。

### 3.4 通用平台

任何能发 POST 的服务都能接。最简形式：

```bash
curl -X POST "https://your-domain.com/hookbox/hook/mytool?token=<RELAY_TOKEN>" \
  -H 'content-type: application/json' \
  -d '{
    "title": "备份完成",
    "body": "数据库快照 2.3GB，耗时 4 分钟",
    "level": "info"
  }'
```

**字段映射规则**（都不填就用默认值）：

| 目标字段 | 依次尝试的 payload 字段 |
|---|---|
| `title` | `title` → `subject` → `name` → `<source> 通知` |
| `body` | `body` → `text` → `message` → `content` |
| `level` | `level` → `severity`（`error`/`critical`/`fatal` → error；`warn`/`warning` → warn；其余 info） |
| `ts` | `ts` → `timestamp`（只认毫秒，秒级会被忽略改用服务器时间） |
| `id` | `id`（用于去重） |

**如果平台发的是表单而不是 JSON**，也能用——非 JSON 的请求体会被当成 `{"raw": "原始内容"}`，标题取默认值，正文为空。这种建议加一层转换（见 3.5）。

**需要 HMAC 的场景：**

```bash
BODY='{"title":"测试"}'
SIG=$(printf '%s' "$BODY" | openssl dgst -sha256 -hmac "$GENERIC_SECRET" | awk '{print $2}')

curl -X POST "https://your-domain.com/hookbox/hook/mytool" \
  -H "content-type: application/json" \
  -H "X-HookBox-Signature: $SIG" \
  -d "$BODY"
```

### 3.5 常见场景配方

**监控告警（Uptime Kuma / 阿里云监控 / 腾讯云监控）**

大多支持自定义 webhook body，用模板拼成：

```json
{"title":"[{{STATUS}}] {{MONITOR_NAME}}","body":"{{MESSAGE}}","level":"{{LEVEL}}"}
```

具体变量名看各平台文档。如果平台不支持自定义 body，就在中间加一个转换（n8n / 自写脚本）。

**支付回调（Stripe 等）**

Stripe 的签名格式是 `Stripe-Signature: t=...,v1=...`，签的是 `t.body` 拼接串。**当前版本没内置这个格式**，两种处理：

1. 回调地址不带签名，靠 URL token 鉴权（简单但不推荐用于支付）
2. 在 `server/verify.go` 里加一个 `stripe` 分支，按它的规则算 HMAC

**CI/CD（Jenkins / GitLab CI / GitHub Actions）**

构建结束发一条：

```bash
curl -s -X POST "$HOOKBOX_URL/hook/ci?token=$TOKEN" \
  -H 'content-type: application/json' \
  -d "{\"title\":\"$JOB_NAME 构建$RESULT\",\"body\":\"分支 $BRANCH，耗时 $DURATION\",\"level\":\"$LEVEL\"}"
```

**如果只是想收通知、不想维护 App**

其实可以零代码：企业微信 / 钉钉 / 飞书都有群机器人 webhook，平台直接把消息推过去，手机装个 IM 就收到了。HookBox 的价值在于**自己的界面、自己的历史、自己的数据**，以及能对接没有 IM 机器人的平台。

## 四、测试方法

### 4.1 最快的一条命令

```bash
curl -X POST "https://your-domain.com/hookbox/hook/test?token=<RELAY_TOKEN>" \
  -H 'content-type: application/json' \
  -d '{"title":"测试消息","body":"如果你看到这条，链路是通的"}'
```

返回 `{"ok":true,...}` 且手机弹通知，就全通了。

### 4.2 用脚本测（推荐，省去拼命令）

仓库里 `scripts/` 下有四份现成工具，都不需要装依赖：

```bash
cd hookbox
export RELAY_TOKEN=<你的token>

./scripts/send-test.sh                    # 健康检查 + 投递 + 落库回查，一次跑完
./scripts/send-test.sh -w                 # 加 -w 会先挂 WebSocket，能亲眼看到实时推送
./scripts/send-test.sh -t "部署完成" -b "v1.2.0 已上线" -l warn -s ci
./scripts/send-test.sh -n 5               # 连发 5 条（自动加时间戳，绕开幂等）
./scripts/send-test.sh -H                 # 只做健康检查
```

Windows 原生 PowerShell：

```powershell
$env:RELAY_TOKEN = "<你的token>"
.\scripts\send-test.ps1
.\scripts\send-test.ps1 -Title "部署完成" -Body "v1.2.0 已上线" -Level warn -Count 3
```

脚本正常输出长这样：

```
→ 目标 https://your-domain.com/hookbox
→ token 01adae1d…54a5（已隐藏中段）

【健康检查】
  ✅ 200  ok

【投递】
  ✅ [1] 200 {"duplicate":false,"id":"manual-test:141980f5..."}

【落库回查】最近 3 条
  17:54:29  [info ] manual-test  实时监听验证
  17:53:28  [info ] manual-test  监听模式测试

结论：中转层正常。若手机没收到 → 问题在 App 侧（服务未开 / 未连上 / 被系统杀）。
```

最后那句结论就是这套脚本最大的价值：**把"中转层坏了"和"手机端没收"这两件事分开**。否则一旦手机没弹通知，你不知道该查服务端还是查 App。

还有 `scripts/test.http`，装了 VS Code 的 REST Client 插件后可以直接点着发，12 个预置请求覆盖了正常投递、幂等、错 token、GitHub 事件模拟等场景。

### 4.3 单独挂一个实时监听

```bash
node scripts/watch.js https://your-domain.com/hookbox <你的token>
```

需要 Node 22+（自带 WebSocket，不用装包）。开着它，然后去 GitHub 后台点一次 "Redeliver"，或者从别的终端发请求，推送内容会立刻打出来：

```
17:54:25  · 握手成功
17:54:29  [info ] manual-test → 实时监听验证
         这条应该出现在 WS 里
```

断线会自动重连（指数退避）。这个比看手机方便——不用解锁屏幕就能确认服务端有没有把消息推出去。

### 4.4 本地起一套隔离实例

如果不想拿线上环境试，或者改了服务端代码想先验证：

```bash
./scripts/local-dev.sh              # 127.0.0.1:18080
./scripts/local-dev.sh -p 19000     # 换端口
```

会现场编译 `server/` 并跑起来，数据写在 `server/local-data/hookbox.db`，**不连线上、不碰服务器、不需要 Docker**。启动时会打印 token 和下一步该跑的命令：

```bash
# 另开一个终端
RELAY_TOKEN=<打印出来的token> ./scripts/send-test.sh -u http://127.0.0.1:18080
```

只需要本机有 Go 1.22+。适合做对照实验：线上不正常但本地正常，那问题在部署；两边都不正常，那就是代码。

### 4.5 分环节排查

| 想确认 | 怎么做 |
|---|---|
| 服务活着吗 | `curl https://your-domain.com/hookbox/healthz` → `ok` |
| 能收 webhook 吗 | 上面那条 curl |
| 手机连上了吗 | App 顶部状态灯 |
| 实时推送通吗 | `./scripts/send-test.sh -w`，看 WS 里有没有收到 |
| 历史存下来了吗 | `curl "https://your-domain.com/hookbox/api/messages?token=<TOKEN>&limit=5"` |
| 平台发过来了吗 | 平台后台的投递记录（GitHub 的 Recent Deliveries） |

### 4.6 查看服务器日志

```bash
ssh ubuntu@你的服务器IP
docker logs --tail 50 -f hookbox-relay
```

正常日志长这样：

```
[hookbox] 监听 :8080，数据库 /home/node/data/hookbox.db
[hookbox] POST /hook/test 200 1ms
[hookbox] 拒绝 test: unauthorized
[hookbox] POST /hook/test 401 0s
[hookbox] WebSocket 已连接，当前在线 1
```

## 五、故障排查

### 5.1 App 侧

| 现象 | 原因 | 解决 |
|---|---|---|
| 一直「连接中…」 | nginx 没转发 `Upgrade` 头 | 检查 nginx 配置里的 `proxy_set_header Upgrade` 和 `Connection` |
| 一直「连接中…」 | 证书不可信 | 浏览器打开 `https://域名/hookbox/healthz`，看有没有证书警告 |
| 一直「连接中…」 | 地址填错 | 必须 `https://域名/hookbox`，不能带 `/ws` |
| 「Ns 后重连」反复循环 | token 不对，被 401 | 核对 `.env` 里的 `RELAY_TOKEN` |
| 显示已连接但收不到 | 长连接正常，但广播没到 | 看服务器日志有没有 `POST /hook/... 200` |
| 锁屏后收不到 | 被系统杀了 | 做 2.4 的保活设置 |
| 不弹通知 | 通知权限被拒 | 系统设置 → 应用 → HookBox → 通知，打开 |
| 不弹通知 | 通知渠道被单独关了 | 同上，点进「收到的通知」渠道确认没关 |
| 消息重复出现 | 不应该发生（有去重） | 检查是不是 `id` 每次都不一样，看服务器日志 |

### 5.2 服务端

| 现象 | 原因 | 解决 |
|---|---|---|
| 平台后台 401 `bad_signature` | `GITHUB_SECRET` 和平台填的不一致 | 两边核对，注意有没有多余空格 |
| 平台后台 401 `unauthorized` | URL 上的 token 不对，且没配签名 | 核对 token |
| 平台后台 413 | 请求体超过 1MB | 平台侧减少 payload，或调大 `maxBodyBytes` |
| 平台后台 500 `store_failed` | 数据库不可写 | 看日志，多半是卷权限问题 |
| 容器反复重启，日志报 `unable to open database file: out of memory (14)` | **不是内存问题**，是数据目录属主不对，非 root 用户写不进去 | `docker exec -u root hookbox-relay chown -R node:node /home/node/data` |
| 部署时 `docker pull` 卡住 | 这台机器连不上 Docker Hub | 见部署文档 7.4 |
| 平台显示成功但手机没收到 | 当时手机不在线 | 消息已入库，App 重连成功后会自动补拉最近 200 条 |

### 5.3 已知限制

| 限制 | 影响 | 绕过 |
|---|---|---|
| 补拉只拉最近 200 条 | 离线很久、超过 200 条之前的消息不会自动补 | 在服务端用 `/api/messages` 手动查历史 |
| 单实例 | 不能水平扩展（Hub 在进程内存里） | 自用场景无需扩展 |
| 无消息保留策略 | 数据库会一直增长 | 加定时任务删 30 天前的记录 |
| Stripe 签名未内置 | 支付回调只能用 URL token | 按需扩展 `verify.go` |
| 无速率限制 | 被刷会写满磁盘 | 在 nginx 层加 `limit_req` |

## 六、安全须知

1. **`RELAY_TOKEN` 等于密码。** 泄露了别人就能往你手机发任意通知。换 token 的方法见部署文档第九节。
2. **优先用签名，其次用 URL token。** URL token 会留在平台后台、nginx 访问日志、浏览器历史里。
3. **不要用自签证书。** 安卓会拒绝，而且训练用户忽略证书警告是坏习惯。
4. **容器不要以 root 运行。** 当前配置用 uid 1000 的 `node` 用户。
5. **`raw` 字段存了完整 payload。** 如果接的是支付或带个人信息的平台，注意数据库文件的访问权限和备份文件的存放。
6. **服务器 SSH 建议改用密钥登录。** 密码登录暴露在公网，会被持续爆破。
7. **nginx 访问日志会记录带 token 的 URL。** 介意的话把 `access_log` 关掉或脱敏。

## 七、日常运维速查

```bash
# 看状态
docker compose -p hookbox ps

# 看日志
docker logs --tail 100 hookbox-relay

# 看资源
docker stats --no-stream hookbox-relay

# 重启
docker compose -p hookbox restart

# 备份数据库
docker run --rm -v hookbox_hookbox-data:/d -v "$PWD":/out \
  alpine tar czf /out/hookbox-$(date +%F).tgz -C /d .

# 看数据库里有多少条
docker exec hookbox-relay sh -c 'ls -lh /home/node/data/'

# 清空所有消息（慎用）
docker compose -p hookbox down
docker volume rm hookbox_hookbox-data
docker compose -p hookbox up -d --build
```

数据库是单文件 SQLite，直接拷 `hookbox.db` 就能备份，不需要导出工具。
